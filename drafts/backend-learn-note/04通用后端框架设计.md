## 在项目需求分析前，应该思考

- 当前项目用户最痛点的问题是什么？
- 用户功能的最小闭环是什么？ 内容查询 & 筛选？
- 辅助最小闭环的实现到项目上线，需要什么技术 & 方案？ 
  
## 项目需求分析

- 接口服务：提供可靠、可扩展的web服务，集成数据库 + Redis
- 实现最小业务闭环：接口CURD、登录注册（认证）、权限控制（鉴权）
- 服务部署与测试 -> 提供文档（需求、测试、部署、产品）

## 项目技术栈

- Nestjs + TS 作为后端
- ORM库 typeORM 官方数据库对接方案

## 关于接口服务

请求 -> 接口服务

请求数据校验 -> 请求认证（鉴权设计）-> 路由 -> 功能逻辑 -> 数据库操作
    Pipe      Guard(Redis)  Controller   Service   Repository(MySQL)
-> 响应
