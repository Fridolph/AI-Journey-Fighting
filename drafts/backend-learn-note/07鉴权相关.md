## 常见的鉴权方式

- Session/Cookie

优点：简单、易扩展
缺点：安全性低、性能低；服务端存储，多服务同步 session 困难，跨平台困难

- JWT

优点：易扩展、支持移动设备，跨应用调用；相对安全，可承载信息丰富
缺点：刷新与过期处理麻烦；padload不易过大；有中间人攻击

- Oauth

优点：开发、安全、简单、权限指定

缺点：需要增加授权服务器，增加网络请求

注：鉴权 不是 算法/加密， 和 HTTPS 的是不同概念

## JWT

全称是 Json Web Token

- Header 头部
- Payload 载荷
- Signature 签名

最主要的特别是 防CSRF（伪造请求，带上Cookie）；适合移动应用；无状态，编码数据

其工作原理：

通过客户端 POST/login 请求 到服务端，服务端验证通过后返回 Token；

后续客户端的Request Header 中等上 Token ，服务端验证该token，通过后才返回 Data

## API 安全设计

- 通信信道加密
- 通信数据加密
  - 密文 + 加密关键数据
- 通信安全策略
  - 授权中间层、尝试次数、过期策略
